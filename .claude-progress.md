# Costbook — progress

## 2026-08-31 — design build-out, Supabase, and the empty account

**What was done**

- **A22–A34, all thirteen artboards.** Setup wizard (1440 + 768), rate-change
  impact panel and its bulk form, channels on the cost sheet, Settings' five
  tabs, the formula inspector, rate history, landing page, legal/404/error,
  sign-up + verify, join by invitation, password reset, and the wordmark as a
  control.
- **Supabase, live.** Project `eekobxmankctlpodbdll` (Mumbai). Five migrations
  applied and verified against the running project, not just pushed: schema,
  cycle trigger, RLS on all 10 tables, signup bootstrap, and a user-deletion
  constraint fix.
- **Zero mock data.** The store used to seed a 21-dish fixture café into every
  running account. It now starts empty; `lib/data.ts` is imported by tests and
  by nothing that runs.
- **Dev-login** at `POST /api/auth/dev-login` — `dev@costbook.test` /
  `costbook-dev`. 404s in production, verified against a real production build.

**Decisions made**

- No email confirmation for now. A31's verify screen stays built but out of the
  path until a real mail provider is configured; the free tier's sender would
  put an inbox round-trip in front of every test.
- An account starts empty and every app screen sends an unfinished one to the
  wizard. Nobody meets a dashboard reading "0 dishes · average food cost —".
- The org is created with an empty name rather than a guessed one. Deriving a
  café name from an email address is the same class of invention as guessing a
  rate.

**Bugs found and fixed**

- `.field` collision — sign-in fields drew two borders. `app.css`'s
  `.field input` (0,1,1) beat `entry.css`'s `.field-input` (0,1,0), so
  `border: 0` lost on specificity regardless of source order.
- A quantity of zero passed component construction, was stored, and only threw
  at costing time — inside a `useMemo`, so the whole page fell to the error
  boundary. Both builders validate it now, and `tryRecipeCost` keeps a bad row
  from blanking the dashboard, the library or the cost sheet.
- `changed_by` had no `ON DELETE` clause, so a user who had ever changed a rate
  could never be deleted — contradicting the privacy page's own promise.
- The landing page claimed its illustration was "a real café's menu". It was
  not. Relabelled as examples.
- `admin@thebrewapps.com` came from a global rules file belonging to another
  project and was creating real accounts in Costbook's database. Removed from
  the whole environment (28 files), with a rule added so it cannot recur.

## 2026-08-31 — CSS scope
**What was done**: The Ingredients "No rate 32" view rendered no rows. Cause: `app/sign-in/entry.css` claimed to be route-scoped and was not — a plain `.css` import in Next is global, only `.module.css` is scoped. Its `.entry` (`min-height:100vh`, a 600px/1fr grid) also claimed the Add-an-ingredient card, which is `.entry` too, pushing all 32 rows below the fold. `.field`, `.notice`, `.proof`, `.spinner`, `.suggestion`, `.countdown`, `.lock-badge` were leaking the same way. Scoped every selector under `.gate`; renamed `.btn-lg` → `.lp-btn-lg` in landing.css.
**Decisions made**: Scope structurally rather than out-specify — the earlier `.field` doubled-border fix was a specificity patch on this same cause. Added `lib/css-scope.test.ts` holding all three page stylesheets to their namespace; verified it fails on the real bug before trusting it.
**Blockers**: None.
**Next steps**: Cost sheet layout (action bar overlaps the rail).
**Files changed**: `app/sign-in/entry.css`, `app/landing.css`, `app/page.tsx`, `components/entry-shell.tsx`, `app/sign-in/page.tsx`, `lib/css-scope.test.ts`
